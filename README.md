# droidlink

맥북 키보드와 트랙패드를 안드로이드 폰에 **실제 키보드·마우스처럼** 연결해서 쓰는 macOS용 앱. USB, Wi-Fi, 블루투스 테더링으로 연결할 수 있다.

폰에는 [scrcpy](https://github.com/Genymobile/scrcpy)의 서버만 잠깐 띄우고, 맥의 키보드·트랙패드 입력은 droidlink가 직접 폰의 가상 USB 키보드·마우스로 보낸다.
폰에 앱을 설치할 필요가 없고, 맥에는 droidlink 창 하나만 뜬다.

## 설치

### 앱으로 (추천)

앱 안에 adb와 scrcpy 5.0.1 서버가 들어 있어서 따로 설치할 것이 없다.

1. [Releases](https://github.com/ttekkeollug/droidlink/releases/latest)에서 `droidlink-macos.zip`을 받아 풀고 `droidlink.app`을 **응용 프로그램** 폴더로 옮긴다.
2. 처음 한 번은 `droidlink.app`을 **우클릭 → 열기**. (개발자 서명이 없는 앱이라 그냥 더블클릭하면 막힌다)
3. **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 **droidlink**를 켠다. 화면 끝 전환·단축키·제스처에 필요하다.
   새 버전으로 바꾸면 다시 켜야 할 수 있다.

### 터미널로

```bash
git clone https://github.com/ttekkeollug/droidlink && cd droidlink
ln -s "$PWD/droidlink" /usr/local/bin/droidlink
```

`droidlink`를 처음 실행하면 `./build-app.sh`로 앱을 만든다 (Xcode Command Line Tools 필요).
`build-app.sh`는 scrcpy 공식 macOS 빌드를 받아(체크섬 확인) adb와 서버만 앱에 넣고, universal `droidlink.app`과 `droidlink-macos.zip`을 만든다.

폰: **설정 → 휴대전화 정보 → 빌드번호 7번 탭** → 개발자 옵션 → **USB 디버깅** 켜기.

## 사용

```bash
droidlink                          # 창을 띄우고 연결 (USB 우선, 없으면 무선)
droidlink pair 192.168.0.12:41234 123456   # 무선 디버깅 페어링 (최초 1회, Android 11+)
droidlink 192.168.0.12:37123       # 이 주소로 무선 연결
```

### droidlink 창

`droidlink`를 실행하면 작은 설정 창이 뜨고 바로 연결을 시작한다.

- **연결 / 연결 해제** 버튼으로 폰 연결을 켜고 끈다. USB가 꽂혀 있으면 USB, 없으면 무선으로 자동 연결한다.
  (창을 닫거나 터미널에서 `Ctrl+C`로 끝내도 연결이 정리된다)
- **무선 연결** (맥과 폰이 같은 Wi-Fi):
  - 케이블 없이 (안드로이드 11+): 폰 개발자 옵션 → **무선 디버깅** 켜기 → **페어링 코드로 기기 페어링** →
    창의 *페어링 코드*에 6자리 입력 → **[페어링]** → **[무선 연결]**. 페어링은 처음 한 번만 하면 된다.
    폰의 주소는 Wi-Fi로 자동으로 찾는다. 못 찾으면 폰에 보이는 IP:포트를 *무선 주소*에 넣는다.
  - USB로 한 번만: 케이블로 연결된 상태에서 **[무선 준비 (5555)]** → 케이블을 뽑아도 계속 동작한다 (폰을 재부팅하면 다시 필요).
- **블루투스 연결** (Wi-Fi가 없을 때, Wi-Fi보다 느림):
  1. USB나 Wi-Fi로 연결된 상태에서 **[무선 준비 (5555)]**를 한 번 누른다 (폰을 재부팅하면 다시 필요).
  2. 폰: **설정 → 연결 → 모바일 핫스팟 및 테더링 → 블루투스 테더링** 켜기.
  3. 맥: 폰과 블루투스로 페어링한 뒤, 블루투스 설정에서 폰에 **네트워크로 연결**한다 (맥에 "Bluetooth PAN" 네트워크가 생김).
  4. droidlink 창에서 **[블루투스 연결]** — 블루투스 네트워크의 폰 주소를 찾아 포트 5555로 연결한다.
  - macOS 버전에 따라 블루투스 네트워크(PAN) 연결이 지원되지 않을 수 있다.
- 마지막으로 쓴 무선 주소는 기억해 두고, 다음에 **[연결]**을 누르면 케이블이 없을 때 그 주소로 연결한다.
- **커서 속도** (-7 ~ 7): 폰의 마우스 포인터 속도 설정을 바로 바꾼다.
- **스크롤 속도** (1 ~ 10): 두 손가락 위아래 스크롤 속도. 맥에 저장돼서 다음 실행에도 유지된다.
- **폰 위치** (왼쪽 / 오른쪽): 폰을 맥의 어느 쪽에 둔 것처럼 쓸지. 오른쪽이면 맥 오른쪽 끝 → 폰, 폰 왼쪽 끝 → 맥.
  왼쪽이면 맥 왼쪽 끝 → 폰, 폰 오른쪽 끝 → 맥.

### 화면 끝으로 전환 (듀얼 모니터처럼)

폰이 맥 화면 **오른쪽**에 붙어 있다고 생각하면 된다 (창의 *폰 위치*에서 왼쪽으로 바꿀 수 있다).

- 맥 커서를 화면 **오른쪽 끝**으로 밀면 → 커서와 키보드가 폰으로 넘어간다.
- 폰 커서를 화면 **왼쪽 끝**으로 밀면 → 커서와 키보드가 맥으로 돌아온다.
- 어떤 이유로든 폰에서 못 돌아오면 **Cmd+Option+Esc**를 누르면 바로 맥으로 돌아온다.

### 단축키·트랙패드도 커서가 있는 쪽에서

커서가 폰에 있는 동안은 키보드와 트랙패드 제스처가 **전부 폰으로만** 간다 (맥 단축키가 맥에서 실행되지 않음).

| 맥에서 | 폰에서 동작 |
|---|---|
| Cmd+C / V / X / A / Z | 복사 / 붙여넣기 / 잘라내기 / 전체 선택 / 실행 취소 (Cmd → Ctrl로 바꿔서 보냄) |
| Ctrl | 안드로이드 Meta 키 (Ctrl+Tab = 최근 앱 등) |
| 한/영 (Caps Lock) | 한/영 전환 (갤럭시 물리 키보드 단축키 Shift+Space로 보냄) |
| 두 손가락 위/아래 | 스크롤 |
| 두 손가락 ← → 가로 밀기 | 화면 슬라이드 (홈 화면 페이지, 사진 넘기기 등) |
| 세 손가락 → 오른쪽 스와이프 | 뒤로 |
| 세 손가락 ← 왼쪽 스와이프 | 앞으로 |
| 세 손가락 ↑ 위로 스와이프 | 최근 앱 |
| 세 손가락 ↓ 아래로 스와이프 | 홈 |

커서가 맥으로 돌아오면 모든 단축키와 제스처가 원래대로 맥에서 동작한다.
키가 이상하게 들어가면 `DROIDLINK_DEBUG=1 droidlink`로 실행하면 폰에 있는 동안 맥 키 이벤트가 터미널에 찍힌다.
제스처 감도는 `edge.swift`의 `swipeDistance`(세 손가락), `slideDistance`(두 손가락)로 조절한다.

처음 실행할 때 **손쉬운 사용 권한**을 묻는다: 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 droidlink(터미널에서 실행했다면 터미널 앱)를 켠다.

동작 원리:
- 연결하면 adb로 폰에 scrcpy 서버를 영상·소리 없이 띄우고, adb 터널로 제어 소켓 하나만 연결해 가상 USB 키보드·마우스(UHID)를 만든다.
- `edge.swift`가 맥 커서 위치를 보고 있다가 화면 끝에 닿으면 맥 커서를 멈추고 숨긴 뒤, 이벤트 탭으로 키·마우스 이벤트를 가로채 가상 키보드·마우스 보고서로 보낸다.
- 폰 커서 위치는 `adb shell dumpsys input`으로 읽어 돌아가는 쪽 끝에 닿으면 맥 커서를 풀어 준다.
- 트랙패드 제스처는 MultitouchSupport로 읽어 `input keyevent` / `input swipe`로, 세로 스크롤은 스크롤량을 모아 `input mouse scroll`로 보낸다.

## 요구사항

- macOS 13 이상 (직접 빌드할 때는 Xcode Command Line Tools: `swiftc`)
- Android 9+ (UHID), 무선은 Android 11+
